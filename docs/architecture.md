# Architecture

## Boundary

`hyprland-grid` is a Hyprland 0.56 Lua tiled-layout provider. It owns tiled world structure and viewport state. Hyprland continues to own:

- window and group targets;
- monitor/work-area discovery, including reserved layer-shell areas;
- gaps, borders, rounding, decorations, pseudotiling, and size configuration;
- floating, fullscreen, XWayland, focus, rendering, and animation;
- workspace creation, monitor assignment, and per-workspace layout selection.

The adapter uses only public/current Lua facilities. It does not hook compositor internals.

## Modules

```text
hypr/grid/
├── init.lua       Hyprland provider, event subscriptions, dispatcher adapter
├── engine.lua     workspace state, rows/cells structure, insertion, commands, lifecycle
└── geometry.lua   weight distribution, grid derivation, rectangle predicates,
                   neighbors, alignment, reveal heuristic
```

`geometry.lua` and `engine.lua` have no Hyprland dependency. Tests run them under a normal Lua interpreter. `init.lua` is covered with a fake `hl` surface matching the 0.56 APIs used by the provider.

## State model

One engine contains a map keyed by Hyprland workspace ID:

```lua
workspaces[id] = {
    viewport = {
        x = 0,          -- world coordinate at viewport left
        y = 0,          -- world coordinate at viewport top
        width = 1920,   -- current screen/work-area logical width
        height = 1040,  -- current screen/work-area logical height
        scale = 1,
    },
    rows = {
        {
            height = 1,                     -- weight; rows split the full height
            cells = {
                { key = "window:42", width = 0.5 }, -- weight vs row siblings
                { key = "window:43", width = 1.0 },
            },
        },
    },
    tiles = { /* derived rectangles consumed by the provider */ },
    focus_key = "window:43",
    insertion = "auto",
}
```

`rows` is the single source of truth for tiling structure. `tiles` is regenerated by every `sync` and after every structural command via `Geometry.derive_grid(rows, area)`, which distributes row heights across the full canvas height and cell widths across the full canvas width using water-filling weights (`Geometry.distribute`), honoring `min_height`/`min_width` whenever physically feasible.

Window targets use `window.stable_id`. Group targets use the Lua group's stable process-local identity. A target absent from the recalculate context is deleted from its row structurally (an emptied row is removed); because placement is derived, survivors close ranks automatically. Floating a window therefore parks nothing — retitling inserts a fresh cell at the current anchor. Moving a window to another workspace deletes its old-workspace record before deterministic destination insertion.

## Coordinate spaces

World geometry is monitor-independent and anchored at the origin: the derived canvas always spans `(0, 0)` to `(area.w, area.h)` in Hyprland logical units. The current `ctx.area` provides the global work-area origin and logical screen size.

For viewport scale $s$:

```text
screenX = area.x + (worldX - viewport.x) × s
screenY = area.y + (worldY - viewport.y) × s
screenW = worldW × s
screenH = worldH × s
```

Normal operation uses `s = 1`. Panning translates the viewport freely, including past content edges into empty canvas. `fit all` derives a temporary scale without modifying structure. `reset viewport` restores `(x, y, s) = (0, 0, 1)`, showing the whole work-area rectangle exactly.

A monitor migration changes `area.x`, `area.y`, viewport screen width, and viewport screen height. Because the canvas derives from those dimensions, tiles rescale proportionally while structural proportions survive. Fractional monitor scaling is already represented by Hyprland's logical `ctx.area`.

Hyprland's `target:place` receives translated logical boxes. It then applies standard gaps, reserved window areas, pseudotiling, decorations, and client configuration. `misc:size_limits_tiled` must remain false: Hyprland's current implementation clamps target positions into the work area when that global option is true.

## Geometry invariants

For every present tile, derived from structure:

1. `x`, `y`, `w`, and `h` are finite.
2. Tiles of one row are horizontally contiguous and together span exactly the canvas width; consecutive rows are vertically contiguous and span the canvas height.
3. The positive-area intersection of any pair is empty.
4. Abutting edges are allowed and expected.
5. `w ≥ min_width` and `h ≥ min_height` in world units whenever `count × minimum` fits the axis; otherwise the axis degrades to an even split because the constraint is physically unsatisfiable.

The viewport is independent of tile geometry; panning may leave all tiles fully or partially outside the visible region.

## Spatial navigation

Given focused rectangle $F$, direction $d$, and candidate $C$:

1. Compute centers $f$ and $c$.
2. Reject $C$ unless its center lies in the requested directional half-plane. For right: $c_x > f_x + \epsilon$; the other directions are symmetric.
3. Compute overlap on the perpendicular axis.
4. Assign a lexicographic score:

```text
[
  lanePenalty,
  primaryMetric,
  perpendicularCenterDistance,
  EuclideanCenterDistance,
  stableTargetKey (tie break)
]
```

`lanePenalty` is `0` for positive perpendicular overlap and `1` otherwise. This means any candidate in the same visual lane wins over a diagonal candidate, matching the requested behavior.

For an overlapping candidate, `primaryMetric` is the non-negative gap between facing edges. For a diagonal candidate:

```text
primaryMetric = primaryEdgeGap + diagonal_weight × perpendicularEdgeGap
```

The default `diagonal_weight` is `2`. The remaining score fields produce stable results when candidates share an edge or have equivalent gaps.

Focusing the winner updates `focus_key`, computes a minimal reveal translation, and invokes `hl.dsp.focus({ window = target.window })`. The event subscription suppresses its own nested reveal during this explicit focus dispatch.

## Minimal reveal

The visible world rectangle is:

```text
{
  x = viewport.x,
  y = viewport.y,
  w = viewport.width / viewport.scale,
  h = viewport.height / viewport.scale,
}
```

`viewport_margin` is configured in screen logical pixels and divided by scale for world comparison.

For each axis independently:

- If the focused tile plus two margins fits, move only the violated edge to the margin.
- If the tile fits but the margins do not, move only enough to expose the tile.
- If the tile is larger than the viewport, center it on that axis.
- If it is already comfortable, do not move that axis.

Click/default focus is observed through `hl.on("window.active", ...)`; an internal `reveal` layout message executes the same rule.

## Insertion

Insertion is deterministic and workspace-local; every operation anchors on the focused cell (or the structurally last cell when focus is invalid).

### Automatic / `insert right`

1. First cell: create one row containing it; a solo window therefore fills the whole work area.
2. Otherwise append a new cell immediately after the focused cell inside that row. No shelf wrapping exists — the row grows and cells redistribute proportionally.

### `insert left`

Prepend immediately before the focused cell of the same row.

### `insert down` / `insert up`

Join the row directly below/above the anchor's row. When that row does not exist, one is created at weight `1` so an N-row workspace splits heights evenly. Horizontal placement uses `Geometry.aligned_cell_index`: the row boundary nearest to the anchor's current left edge wins, so windows visually line up across bands on a best-effort basis.

## Movement

- **Horizontal** (`move left/right`): reorder the focused cell within its own row, wrapping at the row's edges. Each cell carries its own width weight while moving, so sizes follow windows rather than slots.
- **Vertical** (`move up/down`): literal demotion/promotion. The focused window leaves its row entirely (an emptied row disappears) and joins the adjacent band below/above — creating it when missing — aligned by its previous left edge like cross-row insertion. Because geometry derives from rows afterward, no overlap or hole can result.

Reveal follows the moved window using the freshly derived rectangle.

## Resize

- **Vertical** (`resize up/down [amount]`, default `resize_step`): transfer height between the focused row and one neighbor row. Growing downward takes from the row below (falling back to above); shrinking gives back symmetrically. The transfer clamps at `min_height`; single-row workspaces refuse vertical resize outright. Rows always sum to the full height, so unbounded growth is impossible by construction.
- **Horizontal** (`resize left/right`): cycle the focused cell's width through the configured ascending `width_presets` list, wrapping from largest back to smallest and vice versa. An explicit signed amount may flip the cycling direction. Displayed width is the cell's weight relative to its row siblings and can never exceed the screen width.

## Lifecycle and special states

- **Workspace switch:** engine state remains keyed by workspace ID; only the visible workspace is recalculated.
- **Workspace destruction:** `workspace.removed` scans live workspace IDs and prunes removed state.
- **Window close:** close callback removes the stable window key structurally; the provider also removes any target absent from a recalculate context. Neighbors heal automatically because geometry is derived afterward.
- **Window move:** `window.move_to_workspace` removes source structure while preserving any already-created destination record.
- **Monitor move/resolution/scale:** the next `ctx.area` updates viewport screen dimensions; the next derivation rescales world boxes proportionally to fill the new canvas.
- **Floating/pinned:** not supplied to the tiled algorithm. Floating parks nothing; retitling inserts fresh at the current anchor.
- **Fullscreen/maximized:** the default Hyprland fullscreen handler overrides visible target geometry while fullscreen. The stored structure is not mutated.
- **Special workspace:** works when assigned `layout = "lua:grid"`; Hyprland applies its special-workspace visual scale after target placement.
- **XWayland:** no separate path. Hyprland's window target handles protocol coordinates after layout placement.
- **Transient dialog:** floating dialogs are excluded. Forced-tiled dialogs are ordinary targets because transient relationships are not exposed in the layout context.
- **Groups:** one row cell per target. Lua exposes the current group window and group object but no stable layout-target identifier; group topology changes can cause deterministic reinsertion.

## Animation

The viewport is a state translation, not a compositor render transform. A pan changes the goal boxes of all present tiled targets. Hyprland's normal window move/resize animation machinery animates those goals. This reuses configured animation curves but costs one placement per visible or offscreen live target.

## Complexity

Let $n$ be present cells, $r$ rows.

- Derivation (`derive_grid` + water-filling): $O(n \log n)$ per materialization.
- Recalculate/viewport translation: $O(n)$ over derived tiles.
- Directional focus: $O(n)$.
- Structural insert/move/remove: $O(r + n)$ worst case due to table shifts plus locate scan.
- Test-only full overlap validation: $O(n^2)$.

The benchmark includes focus, pan, and translation of every tile. At 100 targets under standalone Lua 5.5 on the development machine, updates measured under ~100 µs each and bulk creation stayed far below Hyprland 0.56's 50 ms Lua layout callback watchdog.

## Why Lua, and the native escalation point

Hyprland 0.56's Lua layout provider exposes everything required for keyboard-first structural tiling: target boxes, work area, active/window/workspace metadata, layout messages, focus dispatch, lifecycle events, and per-workspace layout rules.

The missing surface is native interactive manipulation. In Hyprland 0.56.2, `CLuaTiledAlgorithm::resizeTarget` discards `Δ` and `corner`; `moveTargetInDirection` swaps adapter target order without consulting Lua structure. Continuous gesture deltas and layout-owned fullscreen handlers are likewise unavailable.

If those become required, the clean escalation is a native `Layout::ITiledAlgorithm` registered with `HyprlandAPI::addTiledAlgo`. The pure structure engine and tests define the behavior to port. Function hooks or render-coordinate interception are not required for a scale-1 tiled viewport and should remain a last resort.
